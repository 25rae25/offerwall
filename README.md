# 오퍼월 (Offerwall)

광고 미션 참여부터 적립 대기, 포인트 지급까지의 흐름을 구현한 오퍼월 데모입니다.

- 데모: https://offerwall-portfolio.vercel.app
- 데모 계정: `demo` / `1234`

## 기술 스택

| 기술 | 사용한 곳 |
| --- | --- |
| Next.js App Router | 화면과 목업 API Route Handler 구성 |
| TypeScript | 캠페인, 참여, 포인트 도메인 모델링 |
| TanStack Query | 목록 캐시, 무한스크롤, 참여 후 데이터 갱신 |
| Zustand + persist | 인증과 적립 상태 저장, 새로고침 복구 |
| Tailwind CSS | 모바일 중심 UI |

## 주요 기능

- 카테고리·정렬·검색 조건을 URL에 유지하는 캠페인 목록과 무한스크롤
- 일반 캠페인과 미션형 캠페인의 참여 흐름 분리
- 광고주 확인을 가정한 `참여 → 적립 대기 → 적립 완료` 상태 전환
- 회원가입·로그인, JWT 검증, 로그인 후 원래 페이지 복귀

## 문제 해결

### 중복 요청이 포인트 중복 적립으로 이어지지 않게 하기

처음에는 클라이언트의 Zustand 상태만 확인하고 참여를 처리했습니다. 이 방식은 새 탭이나
중복 요청을 막지 못하므로, 참여 확정을 `POST /api/campaigns/[id]/participate`로 옮겼습니다.

API는 토큰을 먼저 검증하고 사용자·캠페인 조합의 참여 이력과 남은 수량을 확인합니다.
중복 또는 소진 상태는 409로 거절하며, 성공 응답을 받은 뒤에만 클라이언트가 적립 대기
상태를 만들고 목록·상세 캐시를 갱신합니다.

### 새로고침 뒤에도 적립 대기 시간을 이어가기

적립 완료를 위한 `setTimeout`은 새로고침하면 사라집니다. 참여 시각과 상태를 함께 저장하고,
상세 페이지와 마이페이지가 다시 마운트될 때 경과 시간을 계산해 남은 시간만 타이머를 겁니다.

이미 대기 시간이 지났다면 즉시 적립 처리하고, `completeReward`가 완료된 참여를 다시 처리하지
않도록 해 여러 화면에서 복구 로직이 실행돼도 포인트는 한 번만 지급됩니다.

## 데모 범위

- 유저와 참여 이력은 인메모리 저장소를 사용해 서버가 재시작되면 초기화됩니다.
- JWT는 구조를 확인하기 위해 Node crypto로 구현했습니다. 실제 서비스에서는 검증된 라이브러리가 필요합니다.
- 미션 정답은 데모 편의를 위해 클라이언트에 있습니다. 운영 환경에서는 서버에서 검증해야 합니다.
- 포인트 상태는 브라우저 localStorage에 저장됩니다.

## 실행 방법

```bash
npm install
npm run dev  # http://localhost:3000
```

## 폴더 구조

```text
app/          # 페이지와 API Route Handler
components/   # 캠페인, 미션, 마이페이지 UI
lib/          # API 호출, 쿼리, JWT, 목업 저장소
store/        # 인증·포인트 Zustand 스토어
types/        # 캠페인 도메인 타입
```
